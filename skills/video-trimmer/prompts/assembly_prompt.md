# 全片組裝指令（Assembly Pass，純文字推論）

你是節目後期的剪輯總監。前面已經把一支長拍帶分成幾個區段，各區段由多模態模型（看得到畫面、聽得到聲音）挑出候選 clip。
每個候選的乾淨台詞、取捨理由、視覺與聲音檢查都已經做好並存在程式端；每個候選有一個編號 `cand`（「區段-序號」，例如 `2-14`）。
現在請你看**整支片**的候選 clip、完整的 Whisper 句子清單（含角色標籤）與參考腳本，只做**組裝決策**：

## 任務
1. **跨區段去重**：同一個意思在不同區段都有嘗試時，只留最後一次完整的版本（可例外，在 `note` 說明）。
2. **補漏**：候選裡沒有、但句子清單中明顯是正式內容且沒有更好版本的句子，可以新增 clip（`cand` 填 null）。
3. **場外角色**：`[OFFSCREEN]` 句子依規則判定：對得上腳本「聲音角色」台詞、或主持人接著回應的提問／反應、或節目效果的即興反應 → 保留為 `role: "offscreen"` 的獨立 clip；倒數、餵詞、流程指令、修改指示、閒聊、用詞討論 → 剔除。`[CUE]` 永遠剔除。
4. **順序**：`final_edl` 陣列的順序就是成片順序。以原片時間順序為預設；只有當內容需要才調整位置（例如同一段的補拍放回它該在的位置），並在該 clip 的 `note` 說明。
5. **段落標籤**：每個 clip 填 `segment`，用腳本的段落名稱。

## 規則
- 一個候選原則上輸出成一個 clip：`cand` 填候選編號，`sentence_ids` 照抄該候選。不要把兩個候選合併成一個 clip，也不要把一個候選拆成兩個。
- 只有在刪減某個候選的句子、或新增 clip 時，`sentence_ids` 才會和候選不同；只有這時才填 `transcript`：實際說出的乾淨台詞（句內重啟 A + A + B 只寫最後一次、句尾殘留的 NG 開頭刪掉、同音錯字對照腳本修正，但字數語序要對應實際發音）。其他 clip 不要填 `transcript`。
- 一個 clip 只含同一角色的句子。嚴禁把前一次嘗試的前半句和後一次的後半句拼接。
- 時間（`source_in`／`source_out`）、取捨理由、視覺與聲音檢查都由程式從句子清單與候選取得，**不要**輸出這些欄位。
- 每個候選編號在 `final_edl` 與 `dropped` 合計最多出現一次。除了最後列出的「候選沒有涵蓋的主持人長句」，不要逐句列出被剔除的 Whisper 句子，也不要重複列舉。

## 輸出（單一 JSON 物件、不要縮排與換行、不要 JSON 以外的文字）

```json
{"final_edl":[{"cand":"1-1","sentence_ids":[9,10,11],"role":"host","segment":"總開場"},{"cand":"1-2","sentence_ids":[12],"role":"offscreen","segment":"總開場"},{"cand":null,"sentence_ids":[52],"role":"host","segment":"短片A·Hook","transcript":"（實際說出的乾淨台詞）","note":"補漏：候選缺的正式句"}],"dropped":[{"cand":"1-7","why":"與 2-3 重複，留後者"},{"sentence_ids":[3,4],"why":"開場 NG，已由 9-11 取代"}],"notes":"整體結構說明"}
```

- `note`：只在新增、刪減句子、非時間順序或例外取捨時填，30 字以內；其他 clip 不要填。
- `dropped`：列被捨棄的候選編號（`cand`），以及提示詞最後「候選沒有涵蓋的主持人長句」中決定不加入的句子（`sentence_ids`），各附 20 字以內的理由；不要列其他句子。
- `notes`：100 字以內。
